# Лабораторная работа № 10 · UML-моделирование

**Университетская информационная система** учитывает научных сотрудников ВГУ, их кафедры, участие в проектах и преподавательскую нагрузку. Сотрудник учебного отдела работает с системой через консольное меню. Для демонстрации в памяти загружаются два факультета, три кафедры, два декана, один проект и один учебный курс. Имена и контакты в примере вымышлены. Данные сеанса хранятся в памяти.

## Прецеденты

| Код | Цель сотрудника учебного отдела | Метод класса University |
| --- | --- | --- |
| UC-01 | Просмотреть структуру и численность | `overview()` |
| UC-02 | Зарегистрировать научного сотрудника и указать его кафедры | `register_researcher(...)` |
| UC-03 | Назначить участие сотрудника в проекте с заданным числом часов | `assign_project(...)` |
| UC-04 | Закрепить курс за преподавателем по номеру курса | `assign_course(...)` |
| UC-05 | Просмотреть кафедры, проекты и курсы научного сотрудника | `workload(...)` |

При назначении участия в проекте сотрудник учебного отдела указывает социальный код, название проекта и часы. Для зарегистрированного научного сотрудника и существующего проекта система создаёт запись участия и подтверждает назначение. Система сообщает причину отказа, если введены некорректные часы, сотрудник или проект отсутствует или участие уже оформлено. При отказе сведения об участии сохраняются в прежнем виде.

Университет состоит из факультетов, факультет из кафедр. Декан связан с факультетом как сотрудник университета. Научный и административный персонал наследуют общие сведения о сотруднике. Преподаватель является научным сотрудником и может вести курсы. Кафедры сотрудника представлены ассоциацией с кратностью `1..*`. Число часов хранится в `Participation`, поскольку оно относится к паре «научный сотрудник — проект». Названия кафедр и проектов служат ключами справочников. У одного преподавателя может быть несколько курсов, у одного курса может быть несколько преподавателей.

## Запуск

Python 3.10 или новее, внешние пакеты для приложения не требуются.

```console
python -m compileall -f src
python -X utf8 src/main.py
```

Для демонстрационного прогона из PowerShell используйте следующий сценарий.

```powershell
Get-Content -Encoding utf8 docs/demo-input.txt | python -X utf8 src/main.py
```

## Генерация кода и обратное проектирование

Модель выполнена в PlantUML. Скрипт `tools/model.py` генерирует Python-каркас по диаграмме классов. Бизнес-логика и консольный ввод-вывод добавлены к каркасу. Обратное преобразование читает Python AST и восстанавливает поля, операции и наследование. Виды ассоциаций и кратности берутся из комментариев `# uml:` возле соответствующих полей.

```console
python tools/model.py forward uml/classes.puml skeleton.py
python tools/model.py reverse src/university.py uml/classes.puml
java -jar plantuml.jar -charset UTF-8 "uml/*.puml"
```

Первую команду запускают в отдельный файл. Каркас содержит сигнатуры и заглушки операций. Диаграмма классов показывает предметные классы из `src/university.py`; функции консольного интерфейса находятся в `src/main.py`.
